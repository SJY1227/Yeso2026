# Figma 디자인 참조

확인일: 2026-10-02. 디자이너가 원본을 관리하며 이 프로젝트에서는 Figma를 읽기 전용으로 참조한다.

원본: [예소 / Page 1](https://www.figma.com/design/ftPSckhNiwJErjkhZhV9iM/예소?node-id=0-1)

## 연결 및 확인 범위

- 재설치 후 계정 확인, 페이지 메타데이터 조회, 대표 화면 2개의 디자인 문맥·스크린샷 조회 성공.
- 페이지 메타데이터 노드 19,863개, 섹션 37개, 240×320 FRAME 노드 502개를 확인했다.
- 502개는 고유 제품 화면 수가 아니다. 시안, 중첩 프레임, 테마 변형, 모션 단계가 포함된다.
- 이 페이지에는 모바일 앱, 브랜딩, 패키지, 모델링 등 다른 작업도 함께 있다. 임베디드 구현에서는 아래 디바이스 관련 구역을 우선 참조한다.
- 프레임 목록·이름·좌표·텍스트는 [figma-index.json](figma-index.json)에 저장했다. 전체 이미지를 내보낸 파일은 아니며 디자인 변경 이후에는 갱신이 필요하다.

## 실제 디자인 문맥과 렌더 확인

두 화면 모두 배경·캐릭터는 이미지 자산, 인사말·시각은 텍스트, 성장 게이지는 도형으로 구분되어 있다. 화면 전체 스크린샷은 비교 기준으로만 사용하고 펌웨어의 단일 배경 이미지로 대체하지 않는다. 첫 펌웨어에는 두 홈 화면을 구현했고 원본 자산 변환 결과와 동일 C++ 렌더러의 PC 미리보기를 생성했다. 시각·인사말·게이지는 코드에서 별도로 그린다. 최초 진단 화면의 수치는 샘플이었다. v0.5 제품 모드의 시계·성장은 실제 저장/시간 상태와 연결했으며 상단 연결/배터리 그림은 아직 정적 자산이다.

첫 펌웨어를 실제 보드에 업로드했으며 사용자가 두 테마의 표시·버튼 전환과 부저 동작 모두 정상이라고 확인했다. [검증 기록](../validation.md)을 참고한다.

## 구현 전 남은 확인

- 현재 사용자 확인 배선: LCD SCLK=D8, MOSI=D10, CS=D2, RES=D1, DC=D0; 버튼 1개=D3; 부저=D11. 자세한 기록은 [parts-list.md](../parts-list.md).
- BL과 사용자 표현의 SC는 사용하지 않는다고 확인했다. SC의 정확한 기판 표기는 아직 확인하지 않았으며 LCD CS=D2와 구분한다. LCD 전원·접지와 MISO 세부 배선은 전달받지 않았다. 이전 하드웨어 테스트는 다른 환경에서 성공했고 소스 코드는 없다.
- 사용자가 Previous/Next/Confirm 3가지 입력을 확정했다. 현재 1개 버튼은 두 번/한 번/800ms 유지로 각각 매핑했다. Figma의 커서·확인창과 조작 의미는 [실행 계약](../docs/product-runtime.md)을 따른다.
- 문서의 개발 환경·펌웨어 구조, 단계별 개발 순서·완료 기준, 통합 테스트·인수 기준은 사용자 요청에 따라 구현 기준으로 채택하지 않는다.
- Figma의 '최종' 명칭은 디자이너가 붙인 구역명이다. 다른 구역과의 차이나 최종 채택 범위를 아직 모두 검토한 것은 아니다.
- 성장 목표는 2026-10-03 사용자의 Figma 우선 결정에 따라 단계별 40·50·60으로 채택했다. 도감 50마리의 전체 콘텐츠 확보나 배터리 실측까지 완료한 것으로 확대하지 않는다.

2026-10-03 추가: 편지·루틴·완료/포기 확인·도감 선택의 원본 문맥은 `context/`, 변환 출처는 `routine-assets.json`에 보관했다. v0.5는 블루베리 원본 `assets/source/routine/105-1391/img1.png`를 추가 변환했다. 먹이 이름 31종은 섹션 466:2033, 몽실이/또비 이름은 106:2527/321:3569에서 확인했다. 확보한 캐릭터 원본은 두 종류, 먹이 원본은 블루베리 한 종류이며 나머지 먹이는 텍스트로 표시한다. `previews/product-v05-contact.png`의 20개 화면은 PC 전용 가상 상태로 렌더한 미리보기이고 기기 진행 기록이 아니다.

상단 시계는 현재 NTP 상태, 성장 게이지는 저장한 캐릭터 상태를 사용한다. 새 UX PDF와 Notion의 성장/조작 차이는 [대조 기록](../docs/source-review-2026-10-03.md)에 모았다. 이번 계정에서는 기존에 수집한 Figma 자료를 사용했으며 최신 원격 디자인 재조회라고 표현하지 않는다.

## 2026-10-04 도감 원본 재대조

사용자가 도감의 디자인 차이를 지적해 Figma 프레임 `106:2527`(몽실이), `466:2350`(블루베리), `321:3569`(또비)를 브라우저에서 읽기 전용으로 다시 확인했다. 현재 계정에는 Figma 플러그인이 설치되어 있지 않아 이번에는 디자인 문맥/API 자산을 새로 내려받지 않았다. 전체 캔버스 대신 위 세 프레임에 직접 접근했다.

- 기존 캐릭터/먹이 도감의 홈 배경·인사말·하단 보라 패널은 임시 구현이었다. 원본은 흰 화면, 상단 '도감'/번호, `(8,62)`에서 시작하는 224px 카드, 좌우 화살표, 하단 알약 버튼이다. 이를 `CatalogRenderer.cpp`로 분리했다.
- 캐릭터 이름은 약 y=88 기준선, 먹이 이름은 y=101, 버튼은 y=269/높이 39로 대조했다. 이는 100% 배율의 브라우저 시각 대조 값이며 레이어 속성 API에서 추출한 정밀 좌표라고 주장하지 않는다.
- 카드는 핑크 테마에서 연보라색, 로봇 테마에서 크림색이다. 테마는 현재 육성 캐릭터를 따른다. 좌우 입력은 도감 항목을 탐색하며 잠긴 항목은 실루엣/자물쇠로 표시한다.
- `tools/generate_catalog_assets.py`는 이미 확보했던 **개별** 원본 `105-1391/imgImage67.png`(아기 양), 핑크/로봇 캐릭터, 블루베리를 도감 크기로 변환한다. 이름·번호·버튼은 네이티브 크기의 안티앨리어싱 텍스트다. 자물쇠는 코드로 그린 대체 아이콘이다.
- `references/*catalog*`은 원본 QA 자료이며 펌웨어 입력이 아니다. `previews/catalog-reference-comparison.png`는 왼쪽부터 원본 캐릭터/구현 캐릭터/원본 먹이/구현 먹이다. 원본의 파란 선택 테두리는 Figma 편집기 표시다.
- **남은 차이:** 원본은 성장 단계별 그림을 별도 항목으로 보여주고 50을 표시한다. 현재 저장 모델/입력은 두 캐릭터 종류의 소유·경험치에 연결되어 있어 `1/2`를 유지한다. 50칸과 단계별 해금·매핑을 구현한 것이 아니다. 로봇의 아기/최종 단계, 양의 최종 단계와 블루베리 외 먹이 그림도 아직 연결하지 않았다. '홈으로' 항목, 먹이 보유량 상세, 미획득 먹이 잠금은 기존 구현의 조작/상태 표현이다.

## 2026-10-04 Figma 연결 후 원본 적용

위 항목은 연결 전 수정 이력이다. 같은 작업에서 Figma 플러그인이 연결되어 **45개 프레임의 디자인 문맥과 스크린샷, 136개 원본 이미지/SVG**를 읽기 전용으로 확보했다. 파일 URL·노드·자산 SHA-256은 `catalog-assets.json`, 레이어 문맥은 `context/catalog-*.txt`에 보관했다. Figma 파일은 수정하지 않았다.

- 몽실이 1·2·3단계: `106:2527`, `106:2601`, `106:2574`. 또비 1·2·3단계: `321:3569`, `321:2364`, `321:2336`. 잠금 실루엣도 각각의 원본을 사용한다. 경험치로 현재 그림 하나를 고르는 방식에서, 수집한 단계별 카드를 탐색하는 방식으로 변경했다.
- 먹이 31종은 섹션 `466:2033`의 개별 프레임을 모두 연결했다. `catalog-geometry.json`은 원본의 슬롯·회전·크롭·이름 위치를 기록한다. 원본 여백을 잘라 임의로 다시 배치하지 않는다. 아기 양과 아이스크림의 회전, 또비 3단계의 내부 크롭도 보존한다.
- 화살표와 상단 바는 원본 SVG다. 카드 `(8,62,224,258)`와 상단 모서리 14px, 캐릭터 버튼 `(69,269,113,39)`, 먹이 버튼 `(75,269,90,39)`, 반지름 19.5px를 적용했다. 고정 글꼴은 20/22/24px로 생성하며 카드·버튼의 모서리에도 안티앨리어싱을 적용한다.
- 확인창은 원본처럼 y=199부터 덮는 패널이다. 기존 공통 모달의 흰 막/흐림을 제거했다. 원본 확인창의 옛 이름 '동글이'와 로봇 테마의 핑크 임시 캐릭터는 현재 도감 이름·선택한 성장 단계로 대체한다. 현재 성장량을 유지하는 선택과 완성 후 다시 키우기의 안내 문구는 상태에 맞게 구분한다.
- Figma의 `/50` 분모를 반영했다. 현재 직접 연결한 캐릭터 카드는 두 종 × 세 단계 = **6개**이며 미확보 44개 콘텐츠를 만든 것이 아니다. 테마는 육성 종을 따르고 같은 종의 세 단계를 먼저 보여준다. 홈 복귀 항목, 먹이 획득/남은 수 상세, 미획득 먹이 잠금은 기존 조작·상태 표현을 유지한다.
- 240×320 LCD는 RGB565를 사용하고 글꼴은 Noto Sans KR의 원래 표시 크기로 래스터화한다. Figma의 데스크톱 Noto Sans Display와 픽셀 단위로 완전히 같다고 주장하지 않는다. 자물쇠는 Figma가 지정한 텍스트 이모지를 로컬 Segoe UI Emoji로 렌더했다. 홈/성장/보상 화면의 그림과 모션 연결은 이번 도감 변경에 포함하지 않는다.

재생성 순서: `tools/fetch_catalog_assets.py` → `tools/prepare_catalog_images.cjs` → `tools/generate_catalog_assets.py`. 내려받은 원본은 저장소에 보관하므로 만료되는 URL에 상시 의존하지 않는다. 생성한 모든 이미지에는 RGB565+8비트 알파 무손실 압축을 적용한다. 전체 스크린샷은 QA용으로만 사용한다.

검증: `tools/test.ps1` 실행 후 `build/catalog-tests.exe build/catalog-direct`, `build/product-tests.exe build/catalog-direct`, `tools/verify_catalog.py`를 실행한다. 출력 디렉터리는 먼저 만든다. 검증기는 실제 C++ 디코더의 이미지 54개를 독립 PNG 픽셀과 비교하고, [원본/구현 비교](previews/catalog-direct/figma-comparison.png)와 [먹이 31종](previews/catalog-direct/foods.png)을 생성한다. 두 테마의 획득/잠금/확인/상세/홈 312개 상태도 버퍼 경계를 검사한다. `.local/catalog-direct-before`가 있는 작업 환경에서는 이전 화면과 비교해 도감 관련 4개 이외 17개 화면의 바이트 일치도 검사한다.

# 2026-10-06: 하루 요약 원본 연결

이름이 `17. 하루 요약 UX`인 소개/마무리만 보던 구현에서, 같은 행의 `255`~`264` 중간 프레임을 포함하도록 대조 범위를 보완했다. `102:2398` → `102:3092/3099/3110/3121/3132/3157` → `102:3170/3191/3246` → `102:3214` 순서다. 로봇 `321:3272`, `321:2513`도 읽어 테마를 대조했다. 최종 캐릭터 구역 `355:5170`에는 별도 요약 화면이 없었다.

소스는 `summary-assets.json`, `context/102-*.txt`, `context/321-*.txt`, `assets/source/summary`에 있다. 비교에서 체크와 성장 막대 값은 각 화면의 예시/실제 fixture에 따라 다르다. 캐릭터의 세 단계 배치는 기존 공통 홈 슬롯을 유지한다. 편지지 `(20,52,202,229)`, 시각/루틴명, 3행 결과, 원본 SVG 체크/화살표/미완료 장식과 인사 말풍선을 연결했다. 원본 마지막 장에 있는 나가기는 조작을 알 수 있도록 모든 결과 장에 표시한다. 데이터가 길면 글꼴 크기를 줄이고 말줄임하며, 단계가 많으면 3행씩 분할한다. 정식 단계별 홈 배치·새 버튼 설계를 확정한 작업은 아니다.
