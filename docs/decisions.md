# 결정 기록

## D01 — 제품 로직은 휴대 가능한 C++로 둔다

채택. 현재 동작 확인된 Arduino·Adafruit 기반 드라이버는 유지하고, 제품 판단은 Arduino를 포함하지 않는 코드로 작성한다. 이유는 보드 없이 시간 경계·중복·재시작 상태를 빠르게 검증하고 UI/드라이버 변경과 분리하기 위해서다. 기존 PDF의 환경 제안을 채택한 결정이 아니다. RTOS·LVGL·새 빌드 시스템 도입은 구체적인 필요가 생겼을 때 별도로 판단한다.

## D02 — 화면과 제품 상태를 분리한다

채택. 화면 번호, 선택 초점, 애니메이션 프레임은 완료·보상 원장이 아니다. 자료의 여러 테마·캐릭터·모션 변형을 같은 루틴 규칙으로 처리하기 위해서다. 임시 하드웨어 확인 기능은 diagnostics로 옮겨 제품 조작에 혼입되지 않게 한다.

## D03 — 제품 상태를 한 흐름에서 변경한다

채택. 시간 판단과 입력을 같은 애플리케이션 경계에서 처리하고, 외부 콜백이 상태를 직접 바꾸지 않게 한다. 비동기 I/O는 필요에 따라 추가하되 “모듈마다 태스크 하나”로 시작하지 않는다. 재검토 조건은 LCD·저장·통신 때문에 실제로 입력/마감 처리 지연이 발생하는 경우다.

## D04 — 상태 계산과 저장·효과 실행을 분리한다

채택. 엔진은 다음 상태와 발생 이벤트를 계산한다. 저장 성공 후에만 상태 공개·연출·전송으로 이어진다. 저장·네트워크의 실패를 순수 로직 테스트와 독립적으로 주입할 수 있고, 완료와 보상 권리를 같은 트랜잭션에 넣기 쉽다. 현재 단계에서 엔진 계산 성공을 영구 저장 성공이라고 표현하지 않는다.

## D05 — 기존 API와 경쟁하는 계약을 만들지 않는다

채택. 2026-10-03 Notion의 claim/sync 계약을 확보했다. 엔진 내부 ID·명령은 로컬 도메인 계약이고 HTTP DTO가 아니다. UUID 인증과 KST 규약을 확인했으며 성장·배터리·ACK의 충돌/빈틈은 [자료 대조](source-review-2026-10-03.md)에 기록한다. 문서에 없는 필드를 다른 팀의 계약으로 만들지 않는다.

## D06 — 값의 출처와 알 수 없음 상태를 보존한다

채택. 미설정 시각, 측정하지 않은 배터리, 미연결 네트워크, 예시 성장치를 실제 값처럼 쓰지 않는다. 첫 홈 렌더러의 샘플 아이콘과 AM 9:10은 하드웨어 확인 자료로 명시한다. 실사용 화면 연결 전에 이 샘플은 실제 상태 표현으로 교체한다.

## D07 — 저장 형식과 파티션을 성급하게 고정하지 않는다

초기 원칙을 유지하며 v0.4에서 구체화했다. 파티션을 바꾸지 않고 FAT 두 스냅샷에 제품 상태를, NVS에는 작은 세대 표식을 저장한다. 스키마·CRC·명시적 인코딩과 저장 후 전체 읽기 검증을 사용한다. 초기 v0.4 한도는 4회차/16단계/256이벤트였다. v0.7은 16회차/16단계/1,024이벤트이며 서버 제품 제한이 아니다. 완료 회신 대조와 백업 후 과거 기록 정리를 구현했다; 삭제/진행 중 수정 계약은 미확정이다.

## D08 — 화면 자산은 추적 가능하게 변환한다

채택. Figma 노드 ID·원본 자산·변환 도구·미리보기·기기 출력의 연결을 유지한다. 전체 스크린샷을 제품 화면으로 붙이지 않는다. 캐릭터 종류나 성장 단계를 추가할 때 엔진 분기 대신 콘텐츠 매핑을 늘리도록 설계한다. 모든 모션을 풀 프레임 RGB565로 쌓는 방식은 실제 자산 크기 예산을 검토하기 전 채택하지 않는다.

## D09 — 조작 의도를 공통으로 두고 물리 입력만 교체한다

사용자 요청에 따라 갱신. 한 버튼에서는 Tap/DoubleTap/Hold를 Next/Previous/Confirm으로 변환한다. 세 버튼은 왼쪽=Previous, 가운데=Confirm, 오른쪽=Next다. 두 매핑은 함수로 모았고 화면·엔진은 핀이나 유지 시간을 모른다. 현재 300ms/800ms는 조정 가능한 입력 값이다. 포기/취소는 화면에서 선택·확인하며 별도 Back 의도를 두지 않는다.

## D10 — 모든 절전 복귀는 새 시간 동기화를 요청한다

사용자 요구로 확정. `sleepAndResync`가 Wi-Fi 중지, LCD/MCU light sleep, 복귀, `requestSync()` 순서를 묶는다. 처음 저장한 단일 Wi-Fi를 재사용하고 연결/시간 응답 실패는 설정 삭제 없이 재시도한다. 기존 시각이 유효해 보인다는 이유로 새 NTP 요청을 건너뛰지 않는다. known과 fresh를 분리해 오프라인 유지 시각과 이번 복귀 동기화 성공을 구분한다. 최종 앱의 초기 설정 화면은 추후 연결하고 현재는 로컬 USB 설정 도구를 제공한다.

## D11 — 성장 규칙 충돌은 Figma를 우선한다

2026-10-03 사용자 답변 'Figma를 최우선으로'에 따라 채택. 단계별 목표 40·50·60, 누적 40·90·150을 `GrowthPolicy`에 모았다. 먹이 획득과 소비를 구분하고 소비당 +1로 성장시킨다. 서버의 완료 sync당 +1 및 누적 10·20·30을 혼합하지 않는다. 통신 필드는 기존 API를 따르되 성장 상태 수신과 서버 정책 변경이 해결되기 전 자동 동기화를 연결하지 않는다. 화면의 모든 예시 숫자를 일반 제품 정책으로 승격하는 결정은 아니다.

## D12 — 먹이 배정과 소비는 기록을 기준으로 한 번만 확정한다

완료 시 먹이 ID·난수 상태를 완료 권리와 함께 저장한다. 먹이 주기 확인 시 소비 비트·경험치·진화 알림·새 캐릭터 제안을 함께 저장한다. 화면 재진입이나 애니메이션 완료는 지급 근거가 아니다. 스키마 2는 배정된 먹이가 빠진 완료 권리를 거절하고, 스키마 1에서만 미배정 권리를 이행한다. 기존 안내 확인은 소비로 바꾸지 않는다. 현재 같은 가중치의 먹이 추첨과 콘텐츠 순서의 새 캐릭터 제안은 교체 가능한 구현 선택이며 확정된 확률표가 아니다.

## D13 — 하루 집계와 원장 정리를 분리한다

KST 시작 날짜별로 집계하고 자정에 표시 날짜를 전환한다. 날짜 전환이나 요약 확인은 완료 기록·보상·서버 미수신 이벤트를 삭제하지 않는다. 요약 마지막 확인 날짜만 저장한다. 장기 사용의 일정 교체/원장 보관은 별도 구현하며 현재 한 묶음 제한을 숨기지 않는다.

## D14 — 입력·표시 구현을 나누되 제품 상태 소유자는 유지한다

2026-10-03 사용자 리팩토링 요청으로 채택. 화면 종류별 입력 함수는 `ProductInput.cpp`, 제품 상태 확정/복원은 `ProductController.cpp`, 화면 데이터는 `ProductView.h`에 둔다. 파일 분리를 위해 화면마다 상태 객체나 저장 서비스를 새로 만들지 않는다. `RewardLedger`는 후보 상태에서 동작하는 저장 없는 함수로 두고 기존 `commit()`이 유일한 확정 지점으로 남는다. `Drawing`과 화면별 렌더 함수를 분리할 때 직전 21개 화면을 바이트 단위로 대조한다. Figma 규칙과 저장 스키마 변경은 리팩토링에 섞지 않는다.

## D15 — 성장 단계 수집과 현재 육성량을 분리한다

2026-10-04 도감 원본 대조로 채택한 구현 결정. Figma는 같은 종의 성장 단계들을 독립 카드로 보여준다. 종 ID·단계·탐색 인덱스를 구분하고, 최고 도달 단계는 현재 경험치와 별도로 저장한다. 이미 수집한 단계를 다시 키우기 때문에 잠그지 않으며 카드를 선택해 경험치를 올리지도 않는다. 스키마 3을 추가하되 v1/v2 기록은 현재 경험치에서 단계를 유도해 읽는다. 이전 펌웨어에서 이미 지워진 과거 성장 이력은 추정해서 만들지 않는다.

초기 검증 범위는 두 종의 여섯 단계였으나 아래 D16으로 확장·대체했다. 도감 그림의 회전·크롭·이름 좌표는 `catalog-geometry.json`, 종/단계 매핑은 `content/Catalog.h`에 모아 새 콘텐츠가 루틴 엔진이나 GPIO 조건문을 요구하지 않게 한다.

## D16 — 사용자 확정 10종·30단계와 버전 이미지 묶음

2026-10-04 채택. 사용자 10종 × 3단계 지시가 Figma의 /50보다 우선한다. 확정 캐릭터 구역에서 컬러 30개, 도감/최종 화면에서 잠금 14개를 확인했다. 미확보 잠금 16개는 원본으로 위장해 만들지 않고 명시적 물음표로 처리한다. ID 0·1과 v3 저장 구조는 유지하며 새 종을 뒤에 추가한다. 색상·배경은 테마 테이블에 모은다. 홈의 임의 하단 문구/패널을 제거하고 원본 성장 막대를 사용한다.

코드 공간 부족은 파티션 변경 대신 FAT 이미지 묶음/PSRAM 로드로 해결한다. 길이·CRC를 코드와 결합해 검증하고, 청크 수신→임시 파일→전체 재검증→활성화 순서로 진행한다. 제품 기록 파일/NVS 세대와 분리하며 실패 시 재포맷하지 않는다. 사용자 선택에 따라 유휴 홈 Confirm의 동작은 변경하지 않는다. 전달 과제는 디자이너와 서버·앱 개발자 문서로 분리한다.


## v0.7: 통신·연출·보관 경계

사용자 요청에 따라 확보한 API와 Figma로 구현 가능한 부분을 확장했다. HTTPS 작업/물리 입력 수집을 주 상태 흐름에서 분리하고, 모션은 저장된 결과만 표시한다. 그림은 전체 PSRAM 적재 대신 두 압축 스프라이트 캐시를 사용한다. 서버 완료는 로컬 보상과 구분하고 ACK는 실제 완료 시각 회신으로만 확인한다. 과거 기록은 종료/확인/소비/ACK 조건과 영속 백업 후 정리한다. 쓰기 스키마 4, 이전 버전 읽기 지원.

새 뒤로가기 버튼은 논의만 진행했으므로 추가하지 않는다. 배터리 미측정을 임의의 0/100으로 채우지 않는다. 성장은 Figma 40/50/60을 유지한다. 미확보 원본/흰 바탕 export/Figma 호출 한도는 구분해 디자이너 문서에 남긴다.
