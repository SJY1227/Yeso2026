# 디자이너 전달 사항

확인일: 2026-10-06(하루 요약 재대조; 나머지 자산 수량은 기존 조사). Figma는 읽기만 했으며 원본을 수정하지 않았다. 아래 ‘미확보’는 확인한 확정 캐릭터·최종 디바이스 화면·기존 도감 구역 기준이다. 파일 전체에 없다고 단정하지 않는다. 다른 구역에 이미 있다면 해당 노드 링크를 전달해 주면 된다.

## 이미 반영한 기준

- 사용자 확정: **캐릭터 10종 × 성장 3단계 = 도감 30칸**. Figma의 `/50`보다 우선한다. 화면의 `n/30`은 기존 디자인처럼 현재 탐색 위치이며, 보유 수의 합계가 아니다.
- 도감의 컬러 그림은 30단계 모두 연결했다. 미수집 카드는 잠그고, 수집한 단계는 다시 키워도 남는다. 실제 기기에서 미보유 캐릭터를 임의로 지급하지 않는다.
- 캐릭터별 홈 배경, 상단 바, 인사말 글자색, 성장 막대, 도감 카드·버튼·화살표 색을 연결했다. 테마 기준은 현재 함께 키우는 캐릭터다. 도감에서 다른 종을 넘겨보는 것만으로 육성 캐릭터나 테마를 바꾸지 않는다.
- 홈 하단에 임의로 추가했던 보라색 패널, `1단계 0/40`, `아직 일정이 없어요`를 제거하고 원본의 얇은 막대 배치를 적용했다. 성장량은 실제 저장된 값으로 표시한다.
- 사용자 선택에 따라 홈 입력은 기존 방식 유지: **이전·다음 → 도감 선택**, 확인은 대기 성장 흐름/하루 요약 등 현재 상태에 따른 처리. 아무 할 일이 없을 때 확인만 눌러서는 도감이 열리지 않는다. 편지 열기와 먹이 소비에는 확인 입력이 필요하다.

## 우선 요청: 잠금 이미지 16개

[확정 캐릭터 30개](https://www.figma.com/design/ftPSckhNiwJErjkhZhV9iM/예소?node-id=415-4276)의 컬러 그림은 확보했다. [최종 디바이스 화면](https://www.figma.com/design/ftPSckhNiwJErjkhZhV9iM/예소?node-id=355-5170)과 기존 도감을 대조하면 **어두운 잠금 그림은 14/30개**다.

임시 처리는 잠금 카드에 `???`와 잠금 아이콘을 표시하는 것이다. 확보하지 못한 16개를 다른 종의 실루엣으로 대체하거나, 임의로 어둡게 만든 이미지를 확정 원본처럼 사용하지 않았다. 어두운 그림을 코드에서 생성하는 공통 규칙으로 갈 수 있다면 검정 오버레이/불투명도, 눈·발광부 처리, 배경 투명도 기준을 정해 주면 별도 PNG 16개 없이도 가능하다. 현재의 원본 잠금 그림은 발광부가 남아 있어 단순 검정 실루엣과 같지 않다.

전달 형식은 **종의 고정 식별자 + 단계 1/2/3 + normal/locked**가 구분되는 Figma 노드 링크 또는 투명 PNG/SVG가 좋다. 원본 크기를 유지하고, 최종 LCD 배치의 기준점·크기·회전·크롭을 함께 주면 된다. 전체 화면 캡처는 비교 자료이며 제품 이미지 대신 사용하지 않는다.

## 이름과 배치 확인

| 확인할 항목 | 현재 처리 | 필요한 답변 |
|---|---|---|
| 초록 로봇 이름 | 최종 화면 구역의 `저스티스` 사용 | 색상 표의 `저티`가 약칭인지, 어느 것이 정식 이름인지 |
| 물범·파랑 로봇 이름 | 종명으로 임시 표시 | 색상 표의 `할루하`·`호요` 등을 어느 종에 연결할지 확정 |
| 양과 메에 구분 | 양=몽실이, 별도의 뿔 캐릭터=메에 | 두 캐릭터는 서로 다른 원본이다. ‘몽실이/메에’는 같은 양의 이름 충돌로 취급하지 않음 |
| 새 8종의 단계별 도감 배치 | 공통 슬롯에 비율을 유지하고 1→2→3단계 크기를 증가시켜 배치 | 단계별 크기·바닥 기준선 확정. 그림 자체는 이미 있으므로 재제작 요청이 아님 |
| 일반 그림과 잠금 그림의 위치 | 기존 잠금 화면의 좌표는 보존 | 같은 단계의 일반/잠금 크기·위치를 통일할지. 현재 신규 일반 배치와 기존 잠금 프레임 사이 차이가 있음 |
| 홈의 성장 단계 그림 | 컬러 30개를 실제 육성 단계에 연결. 공통 중심/바닥 기준으로 비율 유지 | 1·2·3단계 홈의 크기·기준선 승인. 원본 그림 재제작 요청은 아님 |
| 성장 막대 | 원본 y=291, 높이 8px; 빈 막대 x=45, 채움 시작 x=39 | 원본처럼 시작점이 6px 다른 것이 의도인지. 0%는 빈 막대만, 100%는 끝까지 채움 |
| 상태 아이콘 | Wi-Fi 단절 표시와 배터리 미측정 `?`를 동적으로 덧그림 | 연결 중/오류/미측정의 정식 디자인. 배터리 실측값을 표시하는 구현은 아님 |
| 포기 확인 | 취소/확인 두 선택지, 취소 기본 | 최종 구역 일부의 확인 하나짜리 변형과 어떤 쪽을 사용할지 |
| 하루 요약 | `102:2398`~`102:3214` 및 로봇 `321:3272`의 소개·편지·회차별 결과·종료 화면 반영 | 프레임당 180ms 임시 속도, 3행 초과 시 분할, 모든 결과 장에 나가기 표시, 소개/마무리 수동 확인 동작 검토 |
| 장애 안내 | 작동하는 임시 레이아웃 | 실제 최종 프레임 링크 |

색상표 `466:3707`에는 종명/약칭이 섞여 있으므로 **실제 최종 화면의 색값**을 우선했다. v0.7에서는 10종 배경·상단·종이·패널·버튼과 현재 성장 단계 그림을 편지/루틴/보상 화면까지 연결했다. 먹이는 실제 획득한 31종 중 해당 원본을 쓴다. 편지 알림의 작은 그림은 기존 보라색이며 종별 알림 팔레트는 확인 대상이다.

## 모션 대조와 추가 요청

2026-10-06 하루 요약 연속 프레임을 다시 조회했으며, `355:5170` 최종 캐릭터 구역에는 별도 하루 요약 프레임이 없어 기존 디바이스 구역의 요약과 로봇 변형을 기준으로 삼았다. 기존 상세 통계 패널은 원본 중간 프레임을 놓친 구현이었고 v0.8.2에서 교체했다. [원본/펌웨어 대조](../design/previews/summary/comparison.png), [요약 편지 순서](../design/previews/summary/letter.gif)를 참고한다. Figma 원본은 수정하지 않았다.

Figma native motion 조회에는 키프레임이 없었고 수동으로 늘어놓은 연속 그림을 대조했다. 재생 속도는 확정 디자인이 아니므로 `MotionTiming`의 임시값(편지 100ms, 먹기 260ms, 울기 180ms)으로 분리했다. `motion off/on`으로 끌 수 있고 편지·먹기 재생 중 입력은 연출 건너뛰기로만 쓴다.

| 항목 | 연결한 자료 | 남은 사항 |
|---|---|---|
| 편지 열기 `667:33397` | 9색 스프라이트 시트 × 15프레임, 10종 팔레트 매핑; 봉투 확대/캐릭터 사라짐 전환 | 속도·전환 길이·종이 마지막 장면에서 실제 루틴 화면으로 넘어가는 연출 확인 |
| 요약 편지 `102:3092`~`102:3157` | 봉투 닫힘→열림→종이 상승 6개 그림, 원본 SVG 레이어·테마 색 사용 | `summaryFrameMs=180` 속도 확정. 일반 루틴 편지의 상단 알림 확대 모션과 구분 |
| 울기 `640:2906` | 양·메에·고양이·강아지·물범·곰·토끼, 각 3단계 = 21클립, 클립당 눈물 위치 5개 | 프레임 15장을 한 모션으로 이어 붙이지 않음. 세 행은 서로 다른 성장 단계 |
| 로봇 울기 | 빨강 로봇 구역 일부만 로봇, 나머지는 빈 프레임/메에 복사본. 초록·파랑의 완전한 단계별 연속 그림은 해당 구역에서 미확보 | 정확한 종/단계 클립 링크 요청. 다른 종으로 대체하지 않고 현재 캐릭터 정적 그림 사용 |
| 울기 그림 투명도 | 다운로드된 개별 몸체 21개와 눈물 PNG의 알파가 모두 255이며 흰 사각 배경 포함 | 투명 원본 또는 올바른 export 경로 필요. 현재 결과의 흰 사각형은 아래 검토 시트에 드러남; 원본 파일 전체에 투명본이 없다는 뜻은 아님 |
| 먹기 `466:3157` | 31종의 원래 그림 + 확보한 한입/다음입 40프레임 | 93개 중 나머지 **53개는 원본이 없는 것이 아니라 Figma Education MCP 호출 한도로 추가 추출 대기**. 현재 확보한 연속 구간만 재생 후 성장 화면으로 전환 |
| 진화/완성 | 실제 단계 그림과 성장·진화 알림 연결 | 별도 변신 연속 그림/효과의 확정 노드와 재생 규칙 미확보. 임의의 효과를 확정 기획으로 넣지 않음 |

부족한 잠금 그림 16개, 올바른 로봇 클립, 투명 export 확인과 **이미 존재하는 먹기 원본 추가 추출**은 서로 다른 일이다. 새로 그려 달라는 요청으로 합치지 않는다. 2026-10-06 요약 조회에서는 접근이 복구됐다. 남은 먹기 추출은 이번 요약 수정 범위와 별도로 `design/motion-registry.json`의 `bites[].pending` 53노드를 추출하면 된다. 크루아상은 원본에서 `크로아상`으로 표기돼 이름 연결을 보정했다.

고정 종 ID·단계 원본·테마 색상·노드는 `design/character-registry.json`, 원본 다운로드와 해시는 `design/theme-assets.json` 및 `design/catalog-assets.json`, 좌표 변환은 `tools/prepare_themes.cjs`에 남겼다. 수정할 때 이 연결을 유지해 주면 기존 진행 기록을 바꾸지 않고 자산만 교체할 수 있다.
