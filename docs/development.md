공모전 연동을 위해 사용자 지시대로 서버에 `battery: 100`을 고정 전송한다. 배터리 미측정으로 sync를 막던 런타임 입력을 교체했으며, 이 값은 실측 잔량이 아니다. 기기의 배터리 화면은 미측정을 유지하고 USB 상태에는 `source=contest-placeholder`를 표시한다. Wi-Fi·서버 주소·기기 등록이 완료되면 기존 루틴 수신·완료 전송 경로를 실행한다. 실제 서버 연결은 아직 검증하지 않았다. 앱 BLE 또는 `configure-api.ps1`·`configure-wifi.ps1`로 접속 정보를 설정한다.

앱의 최초 Wi-Fi 전달은 [BLE 계약](ble-wifi-provisioning.md)으로 개발용 구현했으며, 앱 수정·실물 왕복·실사용 BLE 인증/암호화는 남아 있다. 개발 빌드에서는 0.8초 확인을 손을 뗄 때 확정해 5초 설정 입력과 겹치지 않게 한다. 일정 삭제·진행 중 수정·겹치는 루틴 정책, claim 응답 유실 복구, 기기용 성장 상태 조회는 여전히 계약이 부족하다. USB 일정 import는 최초 설정/동일 묶음 재입력용이고 API 일정 갱신과 별개다.

활성 한도는 큰 루틴 16개 × 작은 루틴 16개, 이벤트 1,024개, 스냅샷 64KiB, UTF-8 제목 95바이트다. 로컬 안전 상한이며 서버 제품 제한이 아니다. 과거 백업 파일도 유한한 FAT 공간을 사용한다. 디스크 부족 시 기록을 지워서 계속하지 않는다.

남은 외부 자료와 시각적 한계는 [디자이너 전달 문서](designer-handoff.md), 실제 연결 계약은 [서버·앱 전달 문서](server-app-handoff.md)에 분리했다. 4번째 버튼은 홈 기능을 제안한 논의 상태이며 추가하지 않았다. 실제 공유기/NTP 성공, 실서버 왕복, 물리 정전 내구성과 배터리 전류·사용 시간은 별도 실측 대상이다. [실물 테스트 모드](device-demo.md)로 Wi-Fi 없이 루틴 흐름을 체험할 수 있지만 실제 일정/시간/서버 검증과 구분한다.


## 2026-10-05 재검토와 v0.8 보완

기획 기준·흐름·서버/디자인 전달 문서와 보관된 Notion claim/sync 원문을 코드에 다시 대조했다. 새 서버 계약이나 새 디자인으로 교체한 작업은 아니다.

- 재현한 오류: 내일 일정 수신이나 ACK만으로 도감/확인창이 닫힘. 현재 조작 대상에 실제 변화가 있을 때만 다시 연결하고, 과거 기록 정리로 배열 위치가 바뀌면 날짜별 회차 ID로 연결을 유지한다.
- LCD가 실제 표시한 화면에 입력 context를 부여한다. 선택/단계/화면/연출 역할이 바뀌면 미완료 제스처와 대기 입력을 무효화한다. 늦게 도착한 연출 건너뛰기를 완료 확인으로 바꾸지 않는다. 시계·모션 프레임만 바뀌는 경우는 유지한다.
- JSON 한 문서 뒤의 추가 데이터·NUL·문자열 속 종료 문자를 거절한다. 설정과 HTTP가 같은 검사 함수를 사용하며 JSON 생성 메모리 부족도 확인한다.
- USB/API가 같은 마감 포함 구간 겹침 함수를 사용한다. 등록 결과 저장 중/응답 불확정 상태에서 서버 주소를 바꾸지 않는다. 통신 작업 생성 실패 시 요청을 보내지 않았음을 반영하고 재시도 간격을 둔다.
- 과거 파일은 임시 파일을 영속 검증한 뒤 최종 이름으로 옮긴다. 같은 세대에 다른 내용이 있으면 덮어쓰지 않는다. `backup-state.ps1 -All`은 현 상태와 모든 최종 과거 파일을 내보내고 PC에서 확인한다. 자동 삭제/과거 상태 복원 기능은 아니다.
- 실물에서 절전 뒤 USB의 짧은 응답이 지연되는 경우를 확인했다. 백업·절전 검사 도구는 읽기 전용 상태 조회로 응답을 받아오며, 백업 생성이나 절전 명령을 중복 실행하지 않는다. 백업 도구는 Windows PowerShell 5.1과 PowerShell 7에서 검사했다.
- 기존 스키마 4와 이미지 묶음 dad8398c를 유지한다. 형식 변경이나 진행 초기화를 요구하지 않는다. 실제 새 빌드 검증은 validation.md의 v0.8 기록을 따른다.

배포 전 `tools/verify-build.ps1`로 진입점·C++·헤더와 Arduino 빌드 캐시의 동일성, 내보낸 앱과 캐시 바이너리의 동일성, 자산 헤더/descriptor 버전, 앱·자산 SHA-256을 기록한다. 픽셀/CRC 검사는 `tools/test.ps1`와 기존 자산 검사 도구의 책임이다.

## 2026-10-06 하루 요약 대조

`DailySummary`의 집계와 저장 형식을 유지하고, 날짜별 정렬/3행 페이지 조회를 추가했다. `SummaryRenderer`가 원본 레이어와 동적 기록을 합성한다. UI의 임시 숫자 통계표는 제거했다. `SummaryAssets`의 작은 SVG/글꼴은 앱에 포함하며 기존 FAT 묶음 dad8398c는 유지한다. 원본·코드·차이는 [실행 구조](product-runtime.md), [디자이너 문서](designer-handoff.md), [이미지 배포](image-assets.md)에 기록했다. 네 번째 버튼/루틴 목록은 이번 변경에 포함하지 않았다.
