# 실물 루틴 테스트 모드

2026-10-05, v0.8.1. 사용자가 시험 일정을 넣어 기기에서 확인하도록 요청해 추가했다. 실제 제품의 컨트롤러·입력·렌더러·먹이·성장·요약을 사용하고, 저장소와 시각만 진단용 의존성으로 바꾼다. 제품 서버 연동이나 실제 NTP 성공을 대신하지 않는다.

## 무엇을 시험하는가

큰 루틴 **외출 준비** 아래에 **물 마시기 → 가방 챙기기 → 신발 신기**를 넣는다. 테스트 시작 3초 뒤 편지가 오며 마감은 테스트 시각으로 2시간 뒤, 경고는 1분 전이다. 표시 시각은 2026-01-01 09:00 KST부터 흐르는 모의 시계이며 실제 시스템 시각을 설정하지 않는다. 시간 전진 명령을 합쳐 하루까지만 진행한다.

테스트 중에는 화면 상단에 노란 `TEST` 표시가 나온다. 현재 배선의 D3 한 번=다음, 두 번=이전, 0.8초 유지=확인이다. 편지를 확인으로 열고 루틴의 완료를 선택·확인한 뒤 재확인한다. 먹이 안내·먹이 주기·성장 안내도 확인으로 진행한다. 연출 중 입력은 건너뛰기로만 사용된다.

테스트 진행은 제품용 스냅샷 코덱으로 RAM에만 저장한다. 초기 테스트 캐릭터는 몽실이 0/40이며 실제 캐릭터·도감·성장 기록을 가져오거나 덮어쓰지 않는다. 테스트 동안 서버 작업과 자동 절전은 멈추고, Wi-Fi/NTP 자체의 정상 처리와 실제 시스템 시각은 유지한다.

`demo stop` 또는 보드 재부팅으로 종료한다. 원래 플래시 원장을 다시 읽으며 시험 완료·먹이·성장은 모두 사라진다. 테스트 중 `motion off/on`도 RAM에서만 바뀌고 종료 시 원래 설정으로 돌아온다. 실제 제품 일정이 있었으면 복귀 뒤 실제 현재 시각으로 예약·마감 처리가 재개된다.

## USB 명령

| 명령 | 동작 |
|---|---|
| `demo start` | 새 테스트 초기화. 이미 테스트 중이면 시험 기록만 새로 시작 |
| `demo status` | 실제/시험 세션, 현재 화면·성장, 단계·보상 비트·요약·경과 시각 확인 |
| `demo advance N` | 모의 시각을 N초 전진. 1~86400 범위이며 합산 하루 제한 |
| `demo reload` | RAM 스냅샷을 같은 코덱으로 다시 읽기. 실제 재부팅·정전 내구성 시험은 아님 |
| `demo stop` | 테스트 종료 후 원래 제품 원장 복원 |
| `reboot` | 실제 보드 재부팅. 테스트는 자동 재시작하지 않음 |

테스트 상태에서 허용하는 일반 명령은 `status`, `help`, `reboot`, `input previous/next/confirm`, `motion on/off`뿐이다. 저장 백업·일정 import·API 등록/동기화·Wi-Fi 설정·이미지 전송은 차단한다. 네트워크/이미지/일정 전송 중에는 테스트를 시작하지 않는다.

```powershell
# 수동 체험용으로 시작
./tools/serial.ps1 -Port COM5 -Commands 'demo start'

# 자동 시험: 완료·취소·포기·경고·마감·RAM 복원·실제 기록 복귀
./tools/test-demo.ps1 -Port COM5

# 자동 시험 후 새 편지 상태를 남겨 D3으로 직접 체험
./tools/test-demo.ps1 -Port COM5 -LeaveRunning

# 체험을 마친 뒤 종료
./tools/serial.ps1 -Port COM5 -Commands 'demo stop'
```

자동 시험 중에는 USB로 입력을 보내므로 D3을 함께 누르지 않는다. `-LeaveRunning`일 때 자동 검사가 끝난 뒤 직접 조작한다. 실제 장치 검사 결과는 [검증 기록](../validation.md)에 남긴다.

## 구현 경계

`diagnostics/DemoSession`은 실제 `ProductStore`를 감싸며 비활성일 때 위임하고 활성일 때 RAM 코덱만 사용한다. GPIO/렌더러는 같은 실행 계층을 사용한다. `ProductRuntime`은 세션 전환 시 대기 입력·연출·절전 요청을 무효화하고, 테스트 중 네트워크 실행과 영속 설정 경로를 차단한다. `tests/demo_tests.cpp`는 실제 저장소가 호출되지 않는지와 복원·완료·마감 경로를 검사한다.

## 네 번째 버튼 제안 — 미확정

구성은 이전·다음·확인·홈을 추천한다. 도감에서 홈으로 바로 이동하고, 완료/포기 확인창의 미확정 선택은 취소하며, 루틴의 실제 진행·마감은 계속 유지한다. 이미 확정한 완료·먹이 소비는 되돌리지 않는다. 홈에서 확인으로 진행 중 루틴이나 미처리 먹이로 복귀할 경로도 함께 마련해야 한다. 이는 이번 대화의 설계 제안이며 추가 Intent·GPIO·버튼 동작을 구현한 것은 아니다.

## 하루 요약 확인(v0.8.2)

`./tools/test-demo.ps1 -Port COM5 -LeaveSummary`는 자동 검사를 마치고 새 RAM 시나리오에서 작은 루틴 3개를 모두 완료·먹이 소비한 뒤 요약 소개에 멈춘다. D3 0.8초 유지로 6프레임 편지를 열고, 한 번/두 번으로 결과 장을 넘긴다. 현재 데모는 회차 하나·3단계라 결과 장도 하나다. 확인하면 ‘나가기’→마무리 인사, 다시 확인하면 홈이다. 홈 확인으로 요약을 다시 볼 수 있다. 여러 회차/4단계 이상 분할과 96장 상한은 `summary_tests.cpp`에서 검증한다. `-LeaveRunning`과 `-LeaveSummary`는 동시에 쓸 수 없다.
