## 조작

| 입력 의도 | D3 한 개 | 세 버튼 구성 시 |
|---|---|---|
| Previous | 두 번 짧게 | 왼쪽 버튼 짧게 |
| Next | 한 번 짧게 | 오른쪽 버튼 짧게 |
| Confirm | 800ms 유지 | 가운데 버튼 짧게 |

루틴 화면에서 Previous는 포기, Next는 완료에 `>`를 표시한다. Confirm은 확인창을 연다. 포기 확인창은 **취소가 기본 선택**이며 Previous=취소, Next=확인, Confirm=선택 실행이다. 완료 확인창은 Figma대로 확인 하나를 표시한다. 이때 Previous/Next로 루틴 화면에 돌아가는 동작은 취소 경로를 확보하기 위한 구현 결정이다. 별도의 `Back` 버튼을 요구하지 않는다.

편지는 Confirm으로 연다. 작은 루틴 완료를 저장하면 먹이 획득 → Confirm으로 먹이 주기 → Confirm으로 소비·성장 저장 → 성장 안내 → Confirm으로 다음 작은 루틴/결과 순서다. 진화 알림과 새 캐릭터 선택은 저장한 상태에 따라 사이에 들어간다. 확인창에 있는 동안 경고·마감 등으로 대상 버전이 바뀌면 이전 화면을 대상으로 한 입력은 적용하지 않는다.

2026-10-04 사용자 선택에 따라 홈 입력은 기존 동작을 유지한다. 할 일이 없는 홈에서 Confirm은 도감을 열지 않는다. 홈에서 Previous/Next는 도감 선택창을 연다. Previous=캐릭터, Next=먹이, Confirm=열기다. 도감 안에서는 Previous/Next로 순환 탐색한다. 마지막의 '홈으로' 항목에서 Confirm하면 홈으로 돌아간다. 첫 항목에서 Previous로도 이 항목에 바로 도달한다.

캐릭터 도감은 수집한 성장 단계만 선택할 수 있고 잠긴 항목은 확보한 원본 실루엣과 ???로 표시하고 미확보 원본은 중앙 물음표로 표시한다. 선택 확인창의 기본값은 취소다. 취소하면 보던 카드에 그대로 돌아간다. 미완성 캐릭터를 선택하면 진행량을 유지하고, 완성한 캐릭터의 '다시 키우기'를 확인하면 그 캐릭터의 현재 육성 경험치만 0으로 바꾼다. 소유·최고 도달 단계 기록은 유지한다. 높은 단계의 카드를 선택했다고 경험치를 올리거나 그 단계에서 육성을 시작하지 않는다. 먹이 도감은 미획득 항목을 ???로 표시하고 획득한 먹이의 원본 그림 및 누적 획득/남은 수를 보여준다. 남은 먹이를 선택하면 해당 미소비 권리의 먹이 주기 화면으로 이동한다.

2026-10-04 직접 원본 연결: `content::characterEntry()`가 도감 인덱스를 종 ID와 성장 단계로 바꾼다. 현재 육성 종의 1·2·3단계, 다른 종의 1·2·3단계, 홈 순서다. 그림 배열은 종별 고정 인덱스를 써 탐색 순서와 분리한다. 첫 단계는 종 소유 시, 다음 단계는 누적 40·90 도달 시 수집된다. `highestStage`는 경험치와 별개로 저장되어 다시 키우기 후에도 보존된다. 이는 도감의 수집 개념을 유지하기 위한 구현 결정이다. 사용자 결정에 따라 분모는 `/30`, 탐색은 10종 × 3단계다. 잠금 원본은 14개를 확보했고 나머지 16개는 물음표로 표시한다. 저장 ID 0·1은 보존하고 새 종을 뒤에 추가했다.

## 성장과 하루 요약

2026-10-03 사용자가 'Figma를 최우선으로' 확정했다. `GrowthPolicy`의 단계별 목표는 **40·50·60**, 누적 경계는 **40·90·150**이다. 완료 시 먹이를 배정하고 먹이 소비 시 현재 캐릭터 경험치를 1 올린다. 단계가 바뀌면 진화 알림을 저장하고, 완성하면 아직 소유하지 않은 다음 캐릭터의 선택을 제안한다. 알림/선택 도중 재시작해도 소비를 다시 실행하지 않는다.

먹이 31종은 Figma 도감 이름과 개별 그림을 사용한다. 추첨은 저장되는 PRNG 상태를 이용하며 현재 같은 가중치다. 새 캐릭터는 확보한 콘텐츠 순서대로 제안한다. 이 확률·제안 순서는 교체 가능한 구현 결정이며 Figma에서 확정한 확률표라고 주장하지 않는다. 도감에는 10종 × 3단계와 먹이 31종을 연결했다. 홈/성장/보상에 실제 단계와 먹이 원본을 연결했다. 편지·먹기·울기는 확보한 연속 원본을 사용하며 미확보/불투명 export는 디자이너 문서에 구분했다.

하루 요약은 KST 시작 날짜에 속하는 큰 루틴과 작은 루틴을 집계한다. 포기/마감 전 완료한 작은 루틴도 포함한다. 그날의 큰 루틴이 모두 완료·포기·마감 상태가 되고 미처리 먹이/결과 안내를 확인하면 소개 → 집계 → 마무리 화면을 제공한다. 마지막 확인 여부를 날짜와 함께 저장한다. 홈 Confirm으로 다시 볼 수 있다. 자정에는 새 날짜를 집계하되 이전 기록을 삭제하지 않고, 어제 요약을 향한 입력을 새 일정에 적용하지 않는다. v0.8.2는 Figma `102:2398`부터 `102:3214` 사이의 연속 프레임을 다시 읽고 통계 패널을 제거했다. 소개 → 봉투 열기 → 루틴별 편지지 → 마무리 인사로 연결한다. 시작 시각·루틴 이름·작은 루틴 이름·실제 완료 체크를 표시하며 포기/마감한 회차는 원본의 미완료 장식을 함께 쓴다. 완료 여부는 로컬/서버 DONE 비트의 합집합이며 요약을 읽어도 완료·보상·성장을 바꾸지 않는다.

요약은 시작 시각, 동률이면 고정 회차 ID 순으로 정렬한다. 한 장당 작은 루틴 3개이며 4개 이상이면 이어지는 장으로 나눈다(현재 최대 96장). 이전/다음은 장을 양방향 순환하며 확인은 ‘나가기’로 마무리 인사를 연다. 나가기 표시는 Figma 마지막 장의 것을 모든 장에 공통 적용한 구현 결정이다. 마무리에서 이전/다음은 보던 장으로, 확인은 조회 완료 날짜를 저장한 뒤 홈으로 이동한다. 소개와 마무리에는 원본처럼 별도의 확인 pill을 그리지 않는다. 유휴 홈 확인으로 다시 열면 첫 장부터 시작한다.

요약 편지 모션은 `102:3092/3099/3110/3121/3132/3157` 여섯 개 정적 프레임의 레이어를 재사용한다. native motion 조회에는 키프레임이 없었으므로 프레임당 180ms는 확정 디자인이 아닌 `MotionTiming.summaryFrameMs` 조정값이다. 중간 프레임을 새로 보간하지 않는다. 모션 끄기/건너뛰기와 표시 입력 context를 기존 편지와 동일하게 적용한다. 날짜·회차·페이지가 바뀌면 재생 중이던 연출은 취소된다.

동적 제목은 최대 24px에서 16px까지 조정하고도 길면 UTF-8 글자 경계에서 말줄임한다. 체크 표시와 버튼 위로 넘치지 않는다. 크기가 달라지는 한글은 커버리지 보간으로 계단 현상을 줄이고, 고정 인사/나가기/시각은 표시 크기별 글꼴을 사용한다. 상세 시각 검토는 `design/previews/summary/comparison.png`다.

## 일정과 시간

현재 용량은 큰 루틴 16회차, 회차당 작은 루틴 16개, 문자열당 UTF-8 95바이트, 이벤트 1,024개다. 제품 정책이 아닌 구현 한도다. 겹치는 실행 구간은 명시적으로 거절한다. 마감 우선 여부와 경고 시간은 일정에 반드시 제공한다. 재부팅·절전으로 시작/마감을 지나도 현재 시각으로 따라잡는다.

API 응답 변환과 `applySync()`를 구현했다. 진행 전 미래 일정 갱신, 서버 DONE 병합, 요청과 응답의 완료 시각 대조를 지원한다. 진행 중 구조 수정·삭제 추정·겹침은 보류한다. 종료/결과 확인/먹이 소비/서버 확인을 모두 마친 과거 회차는 백업 후 정리하며 어제/오늘과 누적 획득·성장·수집은 보존한다. USB `importSchedule()`은 최초 묶음/동일 정의 재입력 전용으로 유지한다. 전체 계약은 [서버·앱 전달 문서](server-app-handoff.md)를 따른다.

최초 NTP 성공 전에는 예약/완료/마감을 확정하지 않는다. 이번 부팅에서 동기화한 뒤 네트워크가 끊겼을 때는 유지되는 시스템 시각을 사용한다. 재부팅하면 새 동기화를 기다린다. 시각이 마지막 제품 전환보다 과거로 이동하면 처리를 보류하고 기록을 되감지 않는다. 장기 오프라인 허용 시간·큰 보정 정책은 추가 협의 대상이다.

무조작 60초 뒤 자동 절전한다. 이 값은 조정 가능한 현재 설정이며 확정된 제품 기획 값은 아니다. 다음 시작·경고·마감을 넘지 않도록 타이머를 줄이고, 기본 최대 수면은 300초(시각 미확정이면 30초)다. 입력·부저·USB 일정 전송·동기화 시도 중에는 자동 절전을 미룬다. 매 절전 복귀에서 Wi-Fi/NTP 동기화를 다시 요청한다. 개발 중에는 `idle off`를 쓸 수 있으며 설정은 RAM에만 남는다.

## 저장과 복구

일정·루틴 상태·먹이 배정/소비·캐릭터 소유/성장/수집 단계·요약 확인 날짜·이벤트 목록을 하나의 스냅샷으로 인코딩한다. 구조체 덤프가 아닌 명시적 little-endian 정수, 길이 있는 UTF-8, **쓰기 스키마 4, 읽기 스키마 1~4**, CRC32 형식이다. v3는 v2의 요약 날짜 뒤에 종별 최고 도달 단계 50바이트를 추가한다. 이전 저장은 읽을 때 현재 경험치에서 수집 단계를 유도하며, 다음 정상 저장에서 v4로 기록한다. 옛 펌웨어에서 이미 초기화해 잃어버린 과거 성장량은 복구할 수 없다. v1 완료 권리는 첫 복원 시 먹이를 배정해 저장하고 안내 확인을 소비로 취급하지 않는다. v2 이상에는 완료 권리마다 먹이 ID가 필수다. CRC는 손상 검출용이다. v4를 기록한 뒤 v1~3 전용 펌웨어를 올리면 미지원 스키마로 보류되므로 앱 바이너리만 복원하는 것은 데이터 다운그레이드가 아니다.

1. 기존 16MB 파티션 배치를 유지하고 FAT 파티션의 `state-a.bin`/`state-b.bin`을 번갈아 쓴다.
2. 새 파일을 flush/fsync/close하고 전체 읽기 비교를 수행한다.
3. 작은 NVS 키 `routine-store/generation`에 마지막 저장 세대 번호를 확정한다.
4. 성공한 경우에만 컨트롤러가 상태와 성공 화면을 공개한다.

마운트 전에 데이터 파티션 **전체가 0xff이고 저장 세대 표식도 없는 경우에만** 첫 초기화 권한을 NVS에 기록한다. 실패한 마운트도 wear-levelling 메타데이터를 쓰므로 빈 영역 확인이 먼저다. 초기화 도중 전원 차단은 이 표식으로 다시 시도하며, 첫 generation 저장 이후에는 이 경로를 금지한다. 손상된 파티션을 자동 포맷하거나 지원하지 않는 스키마를 초기 상태로 바꾸지 않는다. 양쪽 파일 유실/이전 세대로의 복귀는 NVS 세대 표식과 대조한다.

쓰기가 실패했어도 새 데이터 일부/전체가 이미 저장됐을 수 있어 같은 부팅에서 재시도하지 않고 오류를 표시한다. 재시작 시 완전하고 검증 가능한 최신 스냅샷이 있으면 이를 복원한다. 한쪽이 손상됐고 다른 쪽만 유효하면 해당 기록을 보존하되 진행은 막는다. 사용자 기록을 묵시적으로 되돌려 중복 보상을 만드는 복구보다 명시적 복구를 택했다. USB 백업 도구는 현재 스냅샷을 불변 파일로 보관한 뒤 PC에서 CRC를 검증한다. 임의 복원/되돌리기는 중복 보상 위험이 있어 자동화하지 않았으며 실제 정전 내구 시험도 별도다.

`earnedRewards`는 완료 권리 이력, `acknowledgedRewards`는 보상 안내 확인, `consumedRewards`는 실제 먹이 소비다. 권리는 회차와 단계로 식별하며 포기·마감으로 지우지 않는다. 완료 전환과 먹이 ID/다음 난수 상태는 같은 저장으로 확정한다. 소비 비트와 경험치/진화 상태 역시 같은 저장으로 확정해 재시작 시 재추첨·중복 경험치를 방지한다. 먹이 도감의 획득 이력은 현재 보관한 일정 묶음에서 계산한다. 운영용 원장 정리는 누적 도감 이력을 별도로 보존하도록 확장해야 한다.

## 개발용 일정 넣기

`examples/schedule.json`은 실행 시점이 2030년인 **예시**다. 실제 날짜·시각, 불투명 회차 ID, 작은 루틴 순서, 마감 정책을 정해 별도 JSON으로 작성한다. 이 파일은 서버 DTO가 아니다. 모든 날짜에 UTC 오프셋이 필수다. USB는 로컬 개발 명령이며 인증된 원격 API가 아니다.

```powershell
python .\tools\compile_schedule.py --help
.\tools\import-schedule.ps1 -Port COM5 -Path '내-일정.json'
.\tools\configure-wifi.ps1 -Port COM5
.\tools\serial.ps1 -Port COM5 -Commands 'status','idle off'
```

전송은 길이 선언 → 오프셋/길이 검증된 64바이트 청크 → CRC/도메인 검사 → 저장 확정이다. 30초 동안 진전이 없으면 RAM 전송 버퍼를 취소한다. 중간에 끊긴 전송은 현재 일정을 수정하지 않는다. 위 도구는 매 청크와 최종 저장 결과의 응답을 확인하며 실패를 성공으로 추정하지 않는다.

## 표시와 미확정 범위

Figma에서 확인한 핑크 편지/루틴/완료 확인/포기 확인/도감 선택의 원본 개별 이미지와 SVG를 사용한다. 전체 프레임 스크린샷은 비교용이고 펌웨어 자산으로 쓰지 않는다. 기록 보관·미동기화·저장 오류 안내는 운영 상태를 위해 추가한 화면이며 최종 디자인 확정본은 아니다.

현대 한글 11,172음절·호환 자모·ASCII를 지원한다. 일반 동적 글자는 22px의 2비트/4단계 농도 비트맵을 크기 조정하며 고정 선택 문구·시계·작은 수치는 전용 안티앨리어싱 글꼴을 쓴다. 한자·이모지는 `?`로 표시하며 긴 제목/단계는 축소·줄바꿈한다. 상단에는 실제 Wi-Fi 단절과 미측정 배터리 `?`를 표시한다. 임의로 추가했던 홈 하단 단계/일정 없음 문구는 제거했고 Figma 성장 막대를 쓴다.

남은 연동은 실제 서버 접속·배터리 unknown·삭제/충돌/등록 복구 계약, 미추출 모션과 투명 자산, 실제 NTP/전력·정전·입력 지연 실측이다. 코드의 API/ACK/과거 보존과 160일 PC 검증을 실서버·장기 실물 사용 완료로 확대하지 않는다. 서버의 완료 sync당 +1 및 누적 10·20·30은 채택하지 않았으며 Figma 규칙에 맞춘 서버 계약 변경이 필요하다.

## v0.6 이미지 분리

[이미지 묶음](image-assets.md)은 기존 FAT의 버전 파일로, 기록과 별도로 설치한다. 두 개의 PSRAM 캐시를 사용하고 캐시 미스에는 파일을 읽는다. 누락/손상 시 내장 글꼴 안내와 USB 설치를 제공하며 사용자 기록을 초기화하지 않는다. 캐릭터별 색과 배경은 `generated/ThemeAssets.*` 테이블을 사용한다. 홈 하단의 임의 패널/문구는 제거하고 Figma 막대만 실제 성장량으로 표시한다.


## v0.7 실행·표시 경계

v4는 v3 필드 뒤에 회차별 remoteCompleted/syncedRewards/apiManaged, 정리된 먹이 누적 31개, retiredBeforeDay를 추가한다. 큰 상태와 스냅샷은 PSRAM에 명시적으로 할당하고 앱 상태 쓰기는 주 실행 흐름만 담당한다. 네트워크 작업은 요청/응답만 전달하고, 물리 입력은 별도 태스크에서 5ms 간격으로 수집한다. 큐가 넘치면 오래된 동작을 재생하지 않고 다시 놓기를 기다린다.

연출은 완료/소비 저장 성공 뒤 시작한다. 건너뛰기·시간 만료·재부팅으로 도메인 수치가 바뀌지 않는다. `motion off/on`은 NVS에 저장한다. 프레임 전체를 저장하지 않고 배경·몸체·눈물·먹이·편지를 합성한다. 이미지 자료는 파일에서 압축 그림 두 개(총 207,288바이트)만 캐시하며 렌더 중 캐시 미스에는 읽기가 발생한다. 제품 입력·렌더·절전은 이미지 설치 중 보류한다. 실제 전송 속도와 사용감은 PC 그림의 속도와 별개다.


## v0.8 동기화·입력·보관 정리

`commitExternal()`은 ACK나 미래 일정 변경에서 화면을 유지하고 실제 현재 대상 변화에서만 재연결한다. 과거 정리로 인덱스가 이동하면 회차 ID로 다시 찾는다. 원장의 generation 변경 자체를 화면 전환 사유로 쓰지 않는다.

`InputSession`은 실제 LCD 전송이 끝난 뒤 입력 context를 공개한다. 다른 화면 전송/자산 설치 중에는 0으로 차단하고, 취소/타임아웃으로 기존 자산을 다시 쓰는 경우도 context를 다시 공개한다. `ContextualGestures`는 context가 바뀌면 시작 중인 탭·홀드를 취소하고 눌린 버튼의 해제를 기다린다. 큐에는 Intent와 context를 함께 넣는다. ProductController의 시간 경계 검사도 유지한다. USB 개발 명령은 현재 상태에 명시적으로 보내는 입력이므로 이 물리 입력 큐를 거치지 않는다.

불변 과거 파일 쓰기는 `platform/FileArchive.*`로 분리해 PC에서도 실제 파일을 사용한 중단/동기화 실패/내용 충돌 검사를 실행한다. `history-<generation>.tmp`를 검증한 뒤 `.bin`으로 옮긴다. 기존 `.bin` 내용이 다르면 오류이며 자동 수리로 덮어쓰지 않는다. `storage list`는 최종 파일만 목록화한다. `backup-state.ps1 -All`의 내보내기와 세대·CRC·PC 해시 확인은 진행 원장/자격증명을 바꾸지 않는다.
