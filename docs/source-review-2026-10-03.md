## 일치하여 반영한 내용

- 큰 루틴에 시작·마감이 있고 작은 루틴은 순서대로 진행한다. 완료와 포기는 서로 다른 결과다.
- 제목의 `4/5`는 현재 작은 루틴 순서다. `전체 1/4`는 하루 큰 루틴 순서다(PDF 7쪽, Figma 102:2301·105:1231). 두 표시를 분리했고 큰 루틴은 KST 날짜별로 센다. 여러 날짜를 보관해도 내일 일정을 오늘 분모에 넣지 않는다.
- 앞/뒤는 선택 이동, 확인은 선택 실행이다(PDF 4쪽, 사용자 확정, Figma 선택 커서). 현재 1개 버튼 제스처는 공통 Previous/Next/Confirm으로 변환한다.
- 포기해도 이미 완료한 작은 루틴 기록과 보상 권리는 보존한다. PDF의 남은 단계 '삭제'는 진행 화면에서 제외하는 의미로 해석하며 감사/동기화 원장을 물리 삭제하지 않는다.

## 확보한 기기 API 계약

[claim 상세](https://app.notion.com/p/claim-3a60ea4df78581cfb0ecf57bd5a5b5cb): `POST /device-api/v1/claim`, 인증 헤더 없음. 필수 `pairingCode`(선행 0 보존, 숫자 10자리 문자열), `deviceUid`, `firmware`. 응답의 `deviceId`, `deviceAccessUuid`를 영속 저장해야 한다. 코드 10분/일회용이며 사용 후 지운다. 404는 없음/이미 사용, 410 만료, 409 다른 계정에 등록. 응답의 serverTime은 상세 문서에서 추론 항목이라고 표시한다. 응답 유실 뒤 같은 코드를 다시 보내면 404가 될 수 있어 claim을 멱등하다고 가정하지 않는다.

[sync 상세](https://app.notion.com/p/push-pull-3a60ea4df78581ef9befd8b993986bd7): `POST /device-api/v1/sync`, 헤더 `X-Device-Uuid`. 필수 `battery`, `firmware`, `completions`, `dates` 네 항목. 완료 없음은 빈 배열. 각 완료는 `smallRoutineId`, `status`(DONE/PENDING), `completedAt`(UTC timestamp, PENDING은 비움). dates는 yyyy-MM-dd이며 최대 3일은 제안이고 확정 상한이 아니다.

응답은 `success/data/error` 봉투 안에 serverTime, accepted, 날짜별 bigRoutines와 smallRoutines다. bigRoutineId/smallRoutineId는 해당 날짜의 실제 행 ID, seriesId는 반복 계열 ID다. 시작/종료 HH:mm은 KST이며 날짜와 결합해 UTC로 변환한다. 명세는 이미 DONE인 항목의 재전송에 경험치를 다시 주지 않는다고 설명한다. DONE→PENDING→DONE 반복과 다중 기기 충돌까지 같은 보장이라고 확대하지 않는다.

인증은 JWT가 아닌 만료 없는 UUID다. refresh/secret은 삭제됐다. 목록에 남은 과거 token/refresh 행을 새 구현의 근거로 사용하지 않는다. 401 DEVICE_UNAUTHORIZED는 자체 복구 경로 없이 재페어링 안내다.

[캐릭터 상세](https://app.notion.com/p/3a60ea4df78581ad9947c65fa98bc344): `GET /api/v1/children/{childId}/characters`는 **앱용**이다. 경험치 증가는 기기 sync에서만, 신규 DONE +1, PENDING으로 취소해도 차감하지 않는다. level=min(3, exp/10+1), exp 상한 30. 완성 뒤 추가 경험치 때 다음 code를 지급한다. 보유 상태는 acquiredAt 순이며 미완성은 최대 1마리다.

## 연동 구현 순서

ERD 보완 확인: 기기 sync는 CHILDREN 행을 잠가 동시 요청에서 같은 완료가 두 번 신규 완료로 집계되는 것을 막는다고 명시한다(문서 내 확정일 2026-09-10). claim은 코드에 해당하는 DEVICES 행을 잠근다. 이 설계는 중복 방지 의도를 뒷받침하지만, 클라이언트의 항목별 ACK·미전송 기록 보존·DONE/PENDING 되돌림 정책을 대신하지 않는다. 실제 DB/서버 구현은 아직 조회하지 않았다. 추가 추출물은 `backend-setup.txt`, `erd-visible.txt`, `kanban-visible.txt`, `device-sync-task.txt`다.

1. 서버 주소·TLS와 앱→기기 핫스팟의 구체적 전달 계약을 받는다. Wi-Fi 저장은 현재 NetworkClock::configure에 연결한다.
2. battery unknown, 부분 ACK, 포기/만료 의미, claim 응답 유실 복구, 일정 수정 충돌을 팀과 확정한다.
3. 서버 DTO 검증과 내부 Schedule 매핑을 별도 어댑터에 둔다. UTF-8/정수 범위·정렬·최대 용량 초과를 검증하고 일부만 조용히 반영하지 않는다.
4. 완료 기록을 먼저 보관하고 같은 smallRoutineId/시각으로 재전송한다. 항목별 반영 확정 전에는 원장을 정리하지 않는다. 새 일정과 로컬 미전송 결과를 함께 조정한다.
5. 이미 채택한 Figma 성장 정책에 서버를 맞추고 기기용 상태 수신을 정한다. 로컬 먹이/성장/도감 원장과 동기화할 때 중복 지급·진행량 덮어쓰기를 방지한다. 매 절전 복귀 Wi-Fi 시간 동기화 요구는 이 작업과 별개로 계속 유지한다.

현재 실서버 주소/계정으로 요청을 보내거나 원격 데이터를 변경하지 않았다. 명세 검토 완료와 실제 API 연동 완료를 구분한다.

## 2026-10-04 추가 구현 대조 (v0.7)

확보한 claim/sync 원문으로 휴대 가능한 DTO 변환·검증과 실제 HTTPS 어댑터를 구현했다. UUID 인증, KST 날짜/UTC 완료 시각, 날짜별 발생 ID를 따른다. accepted 숫자는 완료 확인으로 간주하지 않고 이번 요청의 회차/단계/시각이 응답 DONE과 일치할 때만 로컬 ACK로 기록한다. 아직 실서버에서 이 회신 정책을 검증한 것은 아니다. 진행 중 수정·삭제·겹침·시각 정규화 계약은 보류 항목이다.

상태 쓰기는 v4, v1~4 읽기다. 로컬 보상과 서버 완료를 분리하고 과거 회차는 확인/소비/종료 조건과 영속 백업을 충족한 뒤 정리한다. 160일 진행·150회 완성·다음 종 성장·중간 재부팅을 PC에서 검증했다. 원문에서 서버 주소와 배터리 unknown 표현을 확보하지 못해 실제 통신은 수행하지 않았다.

Figma 최종 화면의 10종 종이·버튼·배경과 30단계 그림, 먹이 31종을 연결했다. 모션 구역은 native timeline 대신 수동 연속 프레임이다. 울기 구역의 세 행은 성장 단계가 다르다. 7종×3단계의 5프레임 눈물 위치, 9색×15프레임 편지, 먹기 40프레임을 연결했다. 빨강 로봇 일부에 빈 프레임/메에 복사가 있고 초록·파랑의 완전한 단계별 클립은 해당 구역에서 미확보다. 개별 울기 export의 알파는 255로 흰 바탕이 포함돼 투명 원본 재확인이 필요하다. 먹기 53개는 원본 노드가 있으나 Figma Education MCP 호출 한도 때문에 추출을 중단했다. 원본이 없다는 판정과 구별한다.

사용자 확정 사항은 그대로다: Figma 성장 40/50/60, 10종×3단계 도감 30칸, 홈 입력 유지, 매 기상 시간 동기화 요청. 4번째 돌아가기 버튼은 논의만 했으므로 코드 의도/핀을 추가하지 않았다.


## 2026-10-05 코드·계약 재검토

보관된 claim/sync 상세 원문, 제품 기준/흐름, 개발/전달 문서를 다시 읽었다. 새로 Figma 파일이나 실서버를 재검증한 것은 아니다. 구현상 문제는 미래 일정 수신의 화면 초기화, 표시와 분리된 입력 큐, 본문 뒤 추가 데이터, 과거 파일 덮어쓰기 가능성이었다. v0.8에서 각각 현재 대상 변화 판별·표시 context·JSON 경계 검사·임시 파일 검증 후 불변 확정으로 보완했다. 완료 ACK만으로 선택창을 닫지 않으며 실제 서버 DONE으로 대상이 달라지면 확인창은 무효화한다.

Notion의 serverTime→RTC 보정 문구는 현재 NTP 기반 구현과 차이가 있다. 시스템 시계에 직접 적용하지 않는다는 사실과 두 시각 소스의 권위/허용 차이 확인 항목을 서버 전달 문서에 명시했다. Figma 성장 우선, 매 기상 시간 동기화, 도감 30칸, 홈 입력 유지와 4번째 버튼 미결정은 바꾸지 않았다.
